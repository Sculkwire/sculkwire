# Changelog

Release notes for sculkwire. Each `## vX.Y.Z` section becomes the GitHub release text when its tag is pushed.

## Unreleased

- `game_stop` also leaves your game alone when the launch record sculkwire finds is stale (a crash left it, sculkwire's game is gone, and the game running now is yours): it stops only a game whose process the record still names, and drops the stale record.
- Your keyboard and mouse are kept out of the game only while sculkwire acts through the in-game agent, as bedrock-mcp does: every tool call that sends input through the agent (`player_act` and play jobs, `game_ui`, `game_input` through the agent, `interact`, `screen` move/act/close, `craft run`), the walk into the world and Save & Quit hold the input lock for their duration and let it go at the end. Between calls you have full control; F9 hands control back for the rest of a call, and the next call locks again. New `game_launch` input `inputLock`: `auto` (default, per call), `on` (a session lock from the moment sculkwire has the agent in the game until `game_stop`, released while a step in `manualSteps` is yours, with `lockNote` saying so) or `off`. The session lock belongs to sculkwire's connection to the agent (new `input.lock` parameter `session`, cleared by the agent when that connection closes), so a sculkwire that exits or is killed never leaves the game locked; after a reconnect sculkwire declares it again. `game_stop` ends it before it stops or detaches and puts back a mode `inputLock` changed. `game_status` reports `inputLock` (`mode`, `locked`, `user`, `session`) and `lockNote` when the lock could not be set (the launch still succeeds). While the lock holds, the keyboard route is kept out too.
- The game never notices losing focus while sculkwire is attached: the agent holds its focus for the connection (`input.lock {focus: true}`, `focusHeld`, cleared when the connection closes), answers its focus queries with its own window, keeps a focus loss from it (replayed once nothing holds focus), tells a game started behind another window once that it is active, and skips its cursor clip and mouse capture while it is behind (`focusGiven`, `cursorKept` in `game_input_lock`). The agent's clicks work with the window in the background, switching away never pauses your game, and your real pointer stays free. Before, a walk into the world on a game started in the background clicked the right tile and nothing opened.
- The lock leaves no visible trace for short calls: its action-bar badge appears only once the lock has held 1 s, is refreshed every 4 s and is cleared when the lock ends, and a badge that ran and failed backs off (1, 2, 4, 8 s) instead of being re-sent every second. The camera permission (`/inputpermission ... camera`) is no longer changed by default; `game_input_lock` `cameraGate: true` turns it on.
- Attaching is quiet: `/script debugger connect` runs through the agent with its output kept out of chat, `/connect` is typed in your chat (or asked of you in `manualSteps`) only with the new `game_launch` input `connect: true`, for a launched game too (commands go through the script debugger), and turning the lock on no longer types a `/testfor @s` line in chat; that line is typed once per world only when a command needs the player's origin.
- The `Debugger connected to host localhost on port …` line of that quiet `/script debugger connect` stays out of chat even when the game reports the connection after the command returned: the agent drops that one line, by its message key, within 5 s of the connect it ran. A `/script debugger connect` you type yourself still shows it. Takes effect once the agent is rebuilt and injected again.
- When the world's tile was clicked and the world does not open, the walk into the world stops at once (at most two double-clicks, about 20 s) instead of clicking for minutes: when a dialog covers the Play screen (such as the World update that makes an old world higher and deeper) it is never confirmed for you, and `manualSteps` asks you to confirm it yourself or open the world. sculkwire then waits for the world in the background without clicking, and a foreground `game_launch` returns.
- After the world's tile was clicked, the agent's UI going quiet is taken for the world loading: the walk waits for it and presses nothing (no Escape that would open the loaded world's pause menu), and it ends recovered as soon as the helper pack answers from the world. `joinRecovery` never says "not recovered" once the world is in.
- `sculk bench`'s scratch world is written as a world of the installed game (`WorldVersion` 1, the game's version in `lastOpenedWithVersion` and `InventoryVersion`), so the game does not offer to update it.
- sculkwire works in your own worlds and never creates one for you. `game_launch` enters `userWorld`, else your saved dev world, else the one of your worlds whose pack lists already name the project's packs (several: the one played last, and `worldNote` says so). When none is found it fails at once, lists your worlds and says to choose one with `game_worlds` `use`. Removed: the `game_launch` inputs `fresh`, `world`, `keep` and `copyFrom` (passing one is refused) and `sculk game check --fresh`; `worldMode` is `user` or `attached`.
- sculkwire no longer writes its marker icon into any world. After a sign-in race the join recovery finds the world's tile by the world's own picture (`world_icon.jpeg`); when the world has none, or two tiles show it, it clicks nothing and asks you to open the world.
- `world_settings` changes the world sculkwire entered or attached to, or your saved dev world, instead of `sculkwire-*` worlds only; any other loaded world is still refused, now also by the agent (`world.set` takes the allowed level name as `world`). Without the agent it rewrites only the saved dev world's `level.dat`, while the game is closed. The agent must be rebuilt and injected again for live changes.
- `sculkwire-` worlds left by earlier versions are still listed and deletable with `game_worlds`; kept and copied ones are never removed automatically, and you may choose one as your dev world. `sculk bench` plays in a scratch world `sculkwire-bench` it deletes when the run ends.

## v0.1.13

- `game_stop` (and `sculk game stop`) never stops a game sculkwire did not launch. A stop in a process that launched nothing, with no launch state recorded (for example after the MCP server that attached to your game was restarted), used to run the install's stop command on whatever game was running, closing your own game without Save & Quit. It now leaves the game alone and only restores the options sculkwire changed.

## v0.1.12

- A command given an option without its value (`sculk game worlds --use`) or an unknown option prints the reason and exits 2 instead of a stack trace. This holds for every `sculk` command.

## v0.1.11

- A muted game's own audio can no longer reach the speakers while the game is being found at start or has just exited during `game_stop`: the watcher moves a stream off the silent sink only while it knows the game's processes (v0.1.10 could take a lingering stream of the stopped game for another app's and move it to the default output).
- `docs/client.md`: attaching on Windows is marked as not yet run against a real Windows game.

## v0.1.10

- Your own Minecraft keeps its sound while sculkwire runs a muted game in the background. PipeWire remembers one output per application name, and both games are named Minecraft, so a Minecraft you started from another install while a headless game ran went to the silent sink. sculkwire now moves a stream of any other process it finds on the silent sink to the default output, within 2 s (checked live: the retail game started while the muted dev game ran was silent for under 2 s, then played on the default output).

## v0.1.9

- `game_launch` works with a game you already opened. When the install's game runs, it attaches instead of refusing (`attached: true`, `worldMode: "attached"`): the game is never restarted, closed or Save & Quit, and nothing in its world is written. Options that need a fresh start (`fresh`, `world`, `keep`, `copyFrom`, `userWorld`, `display`, `width`, `height`, `fps`, `difficulty`, `betaApis`) are named in `worldNote` and not applied; a saved dev world no longer blocks the launch. The game keeps its sound unless `mute: true` is given, which mutes it until `game_stop`.
- A muted game stays silent on Linux. PipeWire's stream restore sent the game to the output it remembered for Minecraft despite the silent sink, so the headless game (muted by default) could play on your speakers. While the game is muted, sculkwire now moves the game's own audio streams onto the silent sink every 2 s (`pactl move-sink-input`; other apps' streams and the default output are never touched, and no stream is muted). `game_stop` keeps them there until the game has exited, so nothing plays during the stop, then removes the silent sink. PipeWire then remembers a sink that no longer exists for Minecraft, so its next start plays on the default output: if you had sent Minecraft to another output, pick it again once. A game you opened yourself and attached with `mute: true` gets its streams moved back to their own output when `game_stop` detaches. `mute: true` now also works for a game you start yourself. `game_status` reports `muted`, and `muteNote` when the sound can still reach the speakers (`pactl` missing, a stream that would not move). The default is unchanged: muted in `headless` mode only.
- With the in-game agent, an attached game gets `/connect` and the content log turned on live, and sculkwire runs `/script debugger connect localhost <port>` and types `/connect localhost:<port>` in chat in the open world itself (both need cheats on; `manualSteps` says so when they fail). It never changes `websocket_encryption` and never confirms a dialog for you: a confirmation a setting opens is cancelled, and a game that requires encrypted websockets gets the step to turn that off itself. Without the agent, `manualSteps` lists the two commands to type. `game_screenshot` of an attached game uses the agent's screenshot.
- `engine_attach` and every other attach reuse an agent already listening on the agent port, from any process, instead of injecting again (the injector refuses a DLL already loaded in the game).
- No command over 1000 characters reaches the game through the in-game agent or `/connect` any more: the game kicks the player for one. `engine_command` refuses it (`invalid_params`), and `game_command` sends it through the script debugger.
- `game_status` reports `inWorld`, `levelId` and `helperNote` for an attached game. `ready` means the script debugger is attached; when the world does not run the helper pack, the helper's tools fail at once with how to add it instead of timing out.
- `game_stop` on an attached game only detaches (`detached: true`): it puts back the settings and `options.txt` keys it changed, closes the listeners and keeps the pack folders the open world uses. `sculk game stop` from another process detaches too.
- `sculk bench` still needs a game of its own and refuses to run while the install's game is open.
- `game_query` `player`, `entities`, `block` and `blocks` answer in a world without the helper pack: when the helper does not answer and the in-game agent is attached, they are read from the game's memory (`source: "engine"`, with a `note`). Entities come from the integrated server with id, type, position, dimension, velocity and health; blocks with their states. Every answer now says its `source`.
- `game_log` reads the content log as the game emits it when no content-log file is written: the in-game agent keeps the newest 2000 messages the game logs (and keeps the game logging them while it is read, even with the content-log file and GUI off), and `game_log` maps them to your files like the file's (`source: "engine"`, with a `note`).
- New agent methods `world.entities`, `world.block`, `world.blocks` and `log.content` ([In-Game Agent](docs/engine.md#protocol)).

## v0.1.8

- `game_status` `dead`, and the respawn a `player_act` call does first, now see a death without a running state stream. On 1.26.60 the death screen is a page neither the in-game agent nor the engine log names, so the player's health is the only sign; when no fresh streamed state exists, the helper pack is now asked for it once. Before, a player killed outside `play` read as alive until a `play` job or the `respawn` action started the stream.

## v0.1.7

- The player no longer stays on the death screen. `player_act` has a `respawn` action, which presses RESPAWN by its control name through the in-game agent when the screen lists it, else clicks the green RESPAWN button where a screenshot shows it (never a fixed spot), and never presses "Game menu"; any `player_act` call that starts while the player is dead respawns first and says so in `respawned`. A `play` run that dies respawns, logs and counts the death, and goes on with the goal, up to `maxDeaths` times (default 3; `maxDeaths: 0` stops at the first death as before). It stops with `died` only after that or when RESPAWN does not bring the player back.
- `game_status` reports `dead` while the death screen is up or the helper streams health 0.
- `game_stop` in a dev world respawns a dead player before Save & Quit.
- On Linux `game_launch` runs the game in the background (`headless`) by default, so it never takes your screen, keyboard or focus; pass `display: "window"` to watch it. Windows keeps its own window as the default.
- `display: "window"` on Linux no longer shows a black bar under the picture or makes the window jitter: inside gamescope the game now runs in its own fullscreen mode (`gfx_fullscreen`, put back by `game_stop`), which fills gamescope's frame and not your monitor. Windowed, Wine gave the game a title bar, so the picture was that much short.
- A launch that failed after opening its listeners no longer keeps ports 19150 and 19151 taken until the MCP server exits: the next launch and `game_stop` close them.

## v0.1.6

- `validate_pack` no longer reports false schema errors (`unknown property "minecraft:geometry"` on a block, `"minecraft:icon"` on an item) with rockide/schemas 0.2, which sculkwire picks up on its own. Rockide 0.2 picks the schema for a `format_version` by version range instead of a list of versions; sculkwire now reads those ranges the way rockide's own build does, so a file gets the schema of its `format_version` again, a version newer than every schema still falls back to the newest one with a `schema.format-version-fallback` warning, and `pack_fix_versions` still suggests `format_version`s.

## v0.1.5

- Your own dev world: choose one of your worlds once with `game_worlds` `action: "use"` (or `sculk game worlds --use <name or level id>`, `--clear-default` to forget it), and `game_launch` and `sculk game check` enter it instead of a throwaway `sculkwire-` world. `userWorld` enters another one for one launch, `fresh: true` (`--fresh`) a test world. Before each launch writes to it, sculkwire backs up its `level.dat`, pack lists and icon (the newest 10 per world, `worldBackup`); it then adds the helper pack and the project's packs to its pack lists (other packs stay, and they stay after `game_stop`), turns cheats on when they are off (the world then awards no achievements; `worldNote` says so), and turns Beta APIs on or sets the difficulty only when asked. The world is never deleted or replaced, and the launch is refused while the game runs.
- `game_stop` in a dev world first tries Save & Quit through the pause menu (up to 45 s), puts the world's own icon back, and keeps the project's development pack folders the world names. `savedAndQuit`, `stopNote` and `keptPackFolders` report it.
- `game_status` and `game_launch` report `worldMode` (`fresh`, `kept`, `copied` or `user`), and `game_status` the saved `defaultWorld`. `game_worlds` marks the saved dev world with `default`.
- `game_query` reads more of the world: `components` (an entity's components and their values), `dynamic_properties` (of the world, the player or an entity), `scores` (objectives and participants), `raycast` (the first block and the entities along a ray) and `entity_properties` (the entity properties a behavior file declares; ids come from the project's packs when not given).
- `wait_until` waits for a condition instead of a fixed sleep: an entity count, a block, a score, an in-world event, a content-log entry, the player reaching a spot, or a number of ticks (up to 55 s). The helper pack checks it every tick, so one call answers.
- `game_events` reads what happened in the world since a cursor: script events, spawns, deaths, hurts, blocks broken and placed, item use, interactions and effects.
- `scene_save`, `scene_reset` and `scene_list`: name a test start once (the blocks and entities in a box, the player's position, inventory with enchantments and lore, game mode, health, time and weather) and put it back in one call. Scenes live in the world, so they last as long as the world: one session in a fresh test world, for good in a kept, copied or dev world.
- `pack_fix_versions` (`sculk validate fix-versions`) raises outdated `min_engine_version` and script module versions, dry run unless `apply: true`, keeping formatting and comments. `min_engine_version` moves to the channel's bedrock-samples release, never past `gameVersion` (`--game-version`), so a fixed pack still loads on the client you test with. Content `format_version`s are suggested, and moved only with `formatVersions: true` when the file still validates.
- `molang_eval` (`sculk molang`) evaluates a Molang expression offline by the game's rules (32-bit floats, degrees, an unset variable stops the expression at 0), with query values you give, or over a range of one query for an animation curve.
- MCP prompts for common flows: `debug_pack_errors`, `playtest_feature`, `test_on_server` and `new_content`. `SCULKWIRE_TOOLSETS` (for example `knowledge,validate`) offers only those toolsets' tools, for clients that load every tool schema up front.

## v0.1.4

- sculkwire no longer runs rgl. Before, `game_launch`, `game_reload`, `validate_pack`, `bds_check`, `gametest_run` and the server sessions copied a Regolith project to a temp folder and ran a plain `rgl run` on its `default` profile there. That ignored the profile and the flags a project needs (`--compat`), built again what `rgl watch` had already built, and `game_launch` and `game_reload` then replaced the folder rgl exported to with that build. Now, when the profile runs filters, every tool reads what your own rgl last built, `.regolith/tmp/BP` and `.regolith/tmp/RP`, and never writes, moves or deletes it. Run `rgl run`, or keep `rgl watch` running, first, and again after editing the sources. A project built with Regolith itself, which moves its build out of `.regolith/tmp`, is used by passing the folder it exported to. See [Regolith Projects](docs/tools.md#regolith-projects).
- `game_launch` and `game_reload`: a pack rgl exported into the game's `development_*_packs` is used in place, with `--compat` too. A build rgl exported elsewhere (a `local` or `exact` target, the com.mojang folder of another install) is copied into a `sculkwire_*` folder, again on every reload. When rgl has not built the project, the launch fails before the game starts, and the reload fails before `/reload` runs, with the step to take. A folder rgl exported to is never written or deleted any more, for a profile without filters too: before, `game_reload` copied the source packs into it and a second export sharing the uuid was deleted; now the second one is reported as a `client.duplicate-pack-uuid` warning, and a `client.rgl-export-differs` warning says when the folder no longer matches the source packs of a profile without filters.
- `validate_pack`: the `regolith` part of the result gains `builtAt` (when rgl last ran, if it can be told) and always has a `message`. When rgl has not built the project, the source packs are validated and `config.json` gets a `regolith.not-built` warning (an error with `regolith: "build"`); when its output lacks one pack, the warning names that pack. The `regolith.build-failed` diagnostic no longer exists.
- `bds_check`, `gametest_run` and `bds_session_start`: when rgl has not built the project, no server starts and the error is `regolith.not-built` (was `regolith.build-failed`); the `status` of `bds_check` is `not-built` (was `build-failed`). A session `reload` no longer builds: with `rgl watch` running it loads the edited sources, and it follows rgl's output when another profile exported somewhere else.
- A pack folder that `config.json` does not name (an example pack below the project) no longer stops `game_launch` and the server tools for a project whose profile runs filters: it is left out, since rgl does not build it.
- `sculk doctor` no longer checks for rgl, since sculkwire does not run it.

## v0.1.3

- Windows Firewall no longer asks for permission on every Bedrock Dedicated Server run. A server now runs from a stable slot folder, `bds-instances/slot-<n>` in the data folder (the lowest free slot), so `bedrock_server.exe` keeps its path and Windows asks at most once per slot. Before, every run used a new folder, which Windows treated as a new program. A kept instance folder is moved to `bds-instances/<id>`.
- On Windows, `sculk setup` and `install.ps1` add inbound firewall rules named `sculkwire BDS` for the server in slots 0 to 3 (allowed on private and domain networks, blocked on public ones), with one elevation prompt. When the rules exist, setup asks nothing; a declined prompt leaves setup successful. `sculk setup --no-firewall` (`install.ps1 -NoFirewall`, `SCULKWIRE_NO_FIREWALL=1`) skips the step. See [Install and Update](docs/install.md#windows-firewall).
- An update from v0.1.2 does not add the firewall rules, since an update never runs `sculk setup`: Windows asks one last time per slot folder, or run `sculk setup` once to add them. `sculk doctor` on Windows has a `firewall` line that says whether the rules are in place.
- The free-port probe for a new server binds loopback instead of all interfaces.

## v0.1.2

- `game_worlds` (and `sculk game worlds`) lists every world of the active game user, marking sculkwire's test worlds, kept ones and the loaded one, and deletes one test world. It refuses the user's own worlds and the world the game has loaded.
- `game_launch` takes `keep`, to continue in the existing test world instead of replacing it, and `copyFrom`, to start from a copy of one of the user's worlds. The original is never changed; the copy is single player with cheats on.
- `game_launch` removes test worlds nobody played for 3 days (never kept or copied ones, never the one it launches) and lists them in `prunedWorlds`. Before, every world name left a `sculkwire-` world behind for good.
- `sculk bench` holds the input lock on the engine route while each run plays, as `player_act` does, so the user's keyboard and mouse cannot disturb a measured run. F9 takes control back; a `play` run then waits until control returns. The keyboard route is unchanged.
- `sculk bench` with an unknown option prints the reason and the usage and exits 2; before, it printed a stack trace.
- `game_builds`, `game_vanilla_packs` and `game_extract_pack` look for the mcbe-gdk-installer game folder under `SCULKWIRE_GDK_ROOT`, else `$XDG_DATA_HOME/mcbe-gdk-linux`, as `game_launch` already did. Before, they searched only `~/.local/share/mcbe-gdk-linux`.
- `sculk bds run`: a `reload` or `reload all` typed on stdin rebuilds a Regolith project first, as `bds_session_command` does, so the reload loads the edited sources.
- The helper pack deployed into test worlds holds only what the game loads (`manifest.json`, `scripts/main.js`); before, its unit test files were copied too.
- An empty `XDG_DATA_HOME`, `XDG_CACHE_HOME` or `XDG_CONFIG_HOME` counts as unset, as the XDG spec says, so the default folder under the home directory is used. Before, an empty value put sculkwire's data, cache and config folders (and the mcbe-gdk-installer folder) relative to the working directory.
- The validator's `reference.function-missing` for a `function` on line 1 of an `.mcfunction` file that starts with a byte order mark points at the right column; before, it was one column too far right.

### Internal

- Shared plumbing lives in `src/core/` (errors, file writes, child processes, CLI entry, MCP results, Regolith builds); every area uses it.
- `src/features.ts` is the one list of built-in features; `src/cli.ts` and the MCP server read it, and `wireFeatures()` connects them instead of import side effects.
- `src/gamefiles/` owns the game on disk: installs, `options.txt`, `level.dat`, world names, Wine and Proton prefixes.
- `src/runtime/engine/` sits below the game client and no longer imports it; the client hands it what it needs. No import cycle is left in `src/`.
- The agent's method names are kept in one table (`src/runtime/engine/methods.ts`), checked by a test against the agent's `METHODS` and the Protocol table of `docs/engine.md`. CI also builds the `debug-rpc` agent and runs the host tests through `native/host-tests.sh`.

## v0.1.1

Published again on 2026-11-12 under the same number, now with the fight, the plan runner and the task steps. An install that already has v0.1.1 keeps the first publication: `sculk update` only moves to a higher version, and an installed version folder is reused. To get this one, delete `versions/v0.1.1` in the sculkwire data folder and the `agent/prebuilt-0.1.1` folder in the sculkwire cache folder, then run the installer again.

- The repository moved to the Sculkwire organization and is public: [github.com/Sculkwire/sculkwire](https://github.com/Sculkwire/sculkwire), mirrored read-only to [gitlab.com/sculkwire/sculkwire](https://gitlab.com/sculkwire/sculkwire). The installers, `sculk update --install` and the prebuilt agent download use the new address; installs made from the old address keep updating through GitHub's redirect.
- Removed the optional decision model: the Jev/Kev advisor of `player_act` `play` and of the `game_launch` sign-in recovery, the `decision_status` tool, the `advisor` and `vision` inputs of `play` with its `model`, `latency` and `advice` result fields and the per-step `by`, `fallback`, `state`, `answers` and `decisionMs`, the `latency` of `player_job` progress, the decision-model question and `--decision` flag of `sculk setup` and the installers, and the `decision` and `uv` checks of `sculk doctor`. Measured runs showed no effect on `play`, the sign-in recovery now reads the screen through the in-game agent, and the calling coding agent is the planner. `play` now chooses every tactic with its built-in scores, and a goal its checks cannot verify runs until the time limit. A `decision` section left in `config.json` is ignored.
- `game_command` through the script debugger answers `ok: false` when the output is one of the game's failure messages (`No targets matched selector`, `Function <name> not found.`), read from the installed game's language file. Before, only syntax errors and unknown commands failed.
- `game_launch` and `game_reload` always copy the project into its own pack folder. Before, when only another folder served a pack's uuid (such as another project folder's `sculkwire_*` copy with the same uuids), that folder was used silently and project edits never reached the game; now it is left alone and reported as a `client.duplicate-pack-uuid` warning that says the game may load it instead.
- `script_profile` no longer charges the time between game ticks to a function. The game samples only while script code runs, and the gap after each tick's last sample (up to 50 ms) went to that sample, so the top function's self time was about the whole capture whatever the load: on BDS 1.26.63, a `Dimension::getEntities` aura showed 4997 ms (99.6%) of a 5 s capture when it ran every tick and 3000 ms (60%) when it ran once a second. A sample is now charged at most one sampling interval (new `intervalMs`, at least 1 ms), the rest is the new `idleMs`, and the same aura measures 100 ms (2%) every tick and 5 ms (0.1%) once a second. `selfPercent` stays percent of the capture duration.
- `player_act` aims in third person on the engine route. With `game_thirdperson` 1 or 2, every action that turns the view (`look_at`, `attack`, `fight`, `shoot`, `goto`, a station `interact`) failed with `anchor_missing` (`camera.direct_look`): the agent wrote the view only into first person's camera, whose stored view stops following the player once the third-person camera is active. `input.look` now writes the active third-person (orbit) camera too, by its look mode, so the player looks where it is told from behind and from the front. When no camera the player follows is found the error is `anchor_missing` (`camera.view`), with the cameras it saw.
- `game_ui` and `game_input` through the agent allow `Return`, `space` and a click on the game's idle overlay ("You've been away for a bit", OreUI route `/idle-route`, read live on 1.26.63.1). Before, every such input was refused as an unlisted OreUI page and `Escape` only opened the pause menu over it, so a session that left the game alone for a while could not get back into the world. That an allowed input closes the overlay is not verified live yet.
- `player_act` `fight` returns what it did as `fight` on its result and in its message on both input routes, also when it fails, times out or is preempted: kills by type, swings, hits, misses, critical hits, hits taken, damage taken and time (`killed 3 husk with iron_sword: 11 swings, 6 hits, 5 misses, 1 critical, took 2 hits for 3.5 damage, in 10.4 s`). `play` stats add `misses` and `hitsTaken`, and a preempted fight's trace step lists its numbers.
- Fixed: `fight` reported `killed nothing` when it turned to another mob right after a killing blow (the dying mob stays in the stream for its death animation). Kills now come from the helper's death log since the fight started.
- `sculk bench combat --scenario husks3`: 3 husks in a tight group at day, summoned 500 ms after `play` started (new scenario field `spawnAfterMs`), goal "kill 3 husks".

- In-game agent (`engine_attach`, `engine_status`, `engine_command`, `engine_player`, `engine_tick`, `engine_screenshot`; `sculk engine attach|status|command|tick|screenshot|player`). A small DLL is injected into the running retail game: under the install's Wine or Proton prefix on Linux and macOS, natively on Windows. It serves newline-delimited JSON-RPC 2.0 on `127.0.0.1:19160`, runs every request that touches the game on its main thread, and resolves its addresses from anchors at attach time, so it is not tied to one build. The DLL is built from `native/` with cargo (rustup's `x86_64-pc-windows-msvc` target, no Windows SDK) or, without cargo, downloaded from the release with its sha256 checked. Hot reload unloads the old copy completely before the new one loads. `engine_command` works right after an attach: the agent replays a real player command's origin, typing `/testfor @s` in chat itself the first time, only while the HUD alone shows. `engine_screenshot` copies the frame the game presents into a PNG at your path, open screens included, without the game's own screenshot (no toast, nothing in its gallery). See [In-Game Agent](docs/engine.md).

The lock fails open, also when the agent unloads. `player_act` and `sculk bench` use the engine route through the built-in input provider while the agent is attached; `input.attack` and `input.use` report the crosshair target and hold their button on request, so `player_act mine` breaks blocks on the engine route.

- Menus and screens (`game_ui`, `sculk game ui`): the current screen and its stack, its controls, and keys, text, clicks and scrolling through the game's own UI, so menus work in the background and on Windows without the foreground. Every input is refused on a store, Marketplace, Minecoins, Dressing Room or persona editor screen except `Escape`; on OreUI pages the agent reads the page's route and allows clicks only on the Play screen and the Settings option pages. A click the game did not read is reported (`ui.click_input`). `game_input` and the `game_launch` sign-in recovery take this route while the agent is attached.
- Inventory, containers, crafting and stations (`player_inventory`, `container`, `craft`, `interact`, `screen`; `sculk player inventory`, `sculk container get`, `sculk craft match|run`, `sculk interact block|entity`, `sculk screen state|move|act|close`): the player's inventory, attributes and armour and any block container, with enchantments by name and the contents of shulker boxes and bundles; recipe matching through the game's own lookup; using a block or an entity like a right click, with `changed` when the used block's state changes (a lever, a button); and the open screen's containers and state, moving items (also into a bundle, through the game's own bundle insert, and on crafter, hopper, dispenser and dropper screens) and running its own action (craft 2x2 and 3x3, trade, stonecut, smelt, enchant, anvil, grindstone, smithing, loom with the requested pattern, cartography, beacon, brewing) as the game's own item requests; `screen close` closes the chat screen too. `player_inventory` and `container get` fall back to the helper pack without the agent.

- `sculk mcp` answers every request it already received when the client closes stdin, and exits only after the answers left stdout (at most 30 s). Before, a client that wrote its requests and closed stdin at once could get a cut-off answer when it read slower than the pipe buffer filled.

## v0.1.0

First release.

- Versioned knowledge for stable and preview: docs, Script API, components, commands, Molang, vanilla examples and changelogs.
- Pack validation with file, line, column and rule code for every problem, including Regolith projects.
- Schemas from [rockide/schemas](https://github.com/rockide/schemas) by default, kept on rockide's newest GitHub release: the source tarball of the newest release tag goes into the cache on first use, the tags are checked again at most once a day (`sculk knowledge update` checks at once), a new release is unpacked and checked before it replaces the old copy, and the last copy is used offline. Without a copy, validation goes on with the engine schemas and `component_lookup` without rockide, and both say so in a `rockide.note`.
- The validator tries rockide first, then the engine schemas from bedrock-samples. Measured on vanilla 1.26.60.5: rockide covers 7476 of 7862 JSON files (the rest are texture lists, `texts/languages.json` and manifests, which have their own check), and 86% of injected entity, block and item errors are caught instead of 18% with the engine first (unknown components and fields), for 9 more held-out vanilla false positives in 3816 files. `--rockide <dir>` (CLI) and `rockide_dir` (MCP) pick a checkout. Results carry `rockide` (release, commit and newest release seen).
- Loot `match_tool` conditions accept a number or `{range_min, range_max}` for `count`, `durability` and enchantment `levels`, as Mojang documents.
- `component_lookup` and `sculk component` include the rockide definition per scope (entity behaviors and components, block and item components, client files): description, properties with types, defaults, allowed values and bounds at the `format_version` matching the channel's game version, plus every version and the versions where it changed.
- Every data source updates on its own, at most one cheap check per source per day, without blocking a tool call and keeping the last copy offline or after a failure. The version pins (samples tags, npm builds, BDS builds, changelog titles) are re-resolved in the background once a day. The MCP server then checks out a newly pinned samples tag while the previous checkout answers, downloads a newer BDS build for the next `bds_check`/`gametest_run`/session, fetches changelogs again when a new article appears and re-indexes the creator docs when `main` moves, all in the background. New typings are installed on next use with the previous install as fallback. A CLI command only refreshes the pins in the background and exits at most 3 seconds after its output; `sculk knowledge update` refreshes everything in the foreground, including installed BDS builds.
- `sculk knowledge status` and `knowledge_versions` list every data source with the version in use, the newest seen upstream and the last check.
- Bedrock Dedicated Server: load checks, headless GameTest runs, sessions and script profiling. A Regolith project whose profile runs filters is built with rgl first and BDS loads the built packs; diagnostics point at the source files (through source maps for generated scripts), and a failed build is a `regolith.build-failed` error with no server started.
- Live game bridge on Windows and Linux: private single-player test worlds, deploy and reload, content log, queries, screenshots and input, with screen-aware sign-in recovery at launch. Deploys leave one folder of the project per pack uuid (a fresh build goes into the project's rgl export folder when there is one) and warn about other packs that share the uuid.
- Player control (`player_act`, `player_job`, `player_state`): human-like camera, pathfinding and combat skills, and the background `play` loop with an optional decision model as advisor.
- Game files of an installed PC (GDK) copy (`game_builds`, `game_vanilla_packs`, `game_extract_pack`, `sculk gamefiles`): game version, the per-version `vanilla_1.x` packs and their extraction from `.brarchive` into plain folders.
- Extensions: packages listed in `SCULKWIRE_EXTENSIONS` or placed in `<config>/extensions` add MCP tools, CLI commands and an in-process input provider for `player_act`; a broken extension is skipped with one stderr line. An extension may also supply the in-game agent's DLL for game folders it recognises (`registerAgentSource`), which replaces the built-in build at attach.
- `sculk bench` measures the player skills in built arenas.
- Installers. `install.sh` (Linux and macOS) and `install.ps1` (Windows) install the newest release into a managed layout, put `sculk` on PATH and run `sculk setup`. Flags: `--yes`, `--decision`, `--register`, `--channel`.
