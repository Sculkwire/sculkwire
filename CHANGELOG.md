# Changelog

Release notes for sculkwire. Each `## vX.Y.Z` section becomes the GitHub release text when its tag is pushed.

## Unreleased

- The repository moved to the Sculkwire organization and is public: [github.com/Sculkwire/sculkwire](https://github.com/Sculkwire/sculkwire), mirrored read-only to [gitlab.com/sculkwire/sculkwire](https://gitlab.com/sculkwire/sculkwire). The installers, `sculk update --install` and the prebuilt agent download use the new address; installs made from the old address keep updating through GitHub's redirect.
- Removed the optional decision model: the Jev/Kev advisor of `player_act` `play` and of the `game_launch` sign-in recovery, the `decision_status` tool, the `advisor` and `vision` inputs of `play` with its `model`, `latency` and `advice` result fields and the per-step `by`, `fallback`, `state`, `answers` and `decisionMs`, the `latency` of `player_job` progress, the decision-model question and `--decision` flag of `sculk setup` and the installers, and the `decision` and `uv` checks of `sculk doctor`. Measured runs showed no effect on `play`, the sign-in recovery now reads the screen through the in-game agent, and the calling coding agent is the planner. `play` now chooses every tactic with its built-in scores, and a goal its checks cannot verify runs until the time limit. A `decision` section left in `config.json` is ignored.
- `game_command` through the script debugger answers `ok: false` when the output is one of the game's failure messages (`No targets matched selector`, `Function <name> not found.`), read from the installed game's language file. Before, only syntax errors and unknown commands failed.
- `game_launch` and `game_reload` always copy the project into its own pack folder. Before, when only another folder served a pack's uuid (such as another project folder's `sculkwire_*` copy with the same uuids), that folder was used silently and project edits never reached the game; now it is left alone and reported as a `client.duplicate-pack-uuid` warning that says the game may load it instead.
- `script_profile` no longer charges the time between game ticks to a function. The game samples only while script code runs, and the gap after each tick's last sample (up to 50 ms) went to that sample, so the top function's self time was about the whole capture whatever the load: on BDS 1.26.63, a `Dimension::getEntities` aura showed 4997 ms (99.6%) of a 5 s capture when it ran every tick and 3000 ms (60%) when it ran once a second. A sample is now charged at most one sampling interval (new `intervalMs`, at least 1 ms), the rest is the new `idleMs`, and the same aura measures 100 ms (2%) every tick and 5 ms (0.1%) once a second. `selfPercent` stays percent of the capture duration.
- `player_act` aims in third person on the engine route. With `game_thirdperson` 1 or 2, every action that turns the view (`look_at`, `attack`, `fight`, `shoot`, `goto`, a station `interact`) failed with `anchor_missing` (`camera.direct_look`): the agent wrote the view only into first person's camera, whose stored view stops following the player once the third-person camera is active. `input.look` now writes the active third-person (orbit) camera too, by its look mode, so the player looks where it is told from behind and from the front. When no camera the player follows is found the error is `anchor_missing` (`camera.view`), with the cameras it saw.
- `game_ui` and `game_input` through the agent allow `Return`, `space` and a click on the game's idle overlay ("You've been away for a bit", OreUI route `/idle-route`, read live on 1.26.63.1). Before, every such input was refused as an unlisted OreUI page and `Escape` only opened the pause menu over it, so a session that left the game alone for a while could not get back into the world. That an allowed input closes the overlay is not verified live yet.
- `game_query` `blocks` and `block`, and `container`, no longer fail near the world floor or build limit: rows outside the dimension's height range are left out (`[]` or `null` when wholly outside).
- The helper pack reports the player from the newest spawn when the world lists more than one handle.
- The helper's player state carries `offhandDamage`, the durability damage of the off-hand item (a shield gains 4 with each husk hit it blocks, measured on 1.26.63).
- Engine calls made one after another no longer take about 57 ms each (measured on retail: `input.move`, `input.look` and `player.state` 25 ms apart, 56 to 58 ms each, while a call after 160 ms of silence took 6 ms): the agent sent every answer as two writes (the line, then its newline) with Nagle's algorithm on, so the newline waited for the client's delayed ACK. Each line is now one write and the agent sets `TCP_NODELAY` on every connection; a call costs its handler's own time.

## v0.1.1

- In-game agent (`engine_attach`, `engine_status`, `engine_command`, `engine_player`, `engine_tick`, `engine_screenshot`; `sculk engine attach|status|command|tick|screenshot|player`). A small DLL is injected into the running retail game: under the install's Wine or Proton prefix on Linux and macOS, natively on Windows. It serves newline-delimited JSON-RPC 2.0 on `127.0.0.1:19160`, runs every request that touches the game on its main thread, and resolves its addresses from anchors at attach time, so it is not tied to one build. The DLL is built from `native/` with cargo (rustup's `x86_64-pc-windows-msvc` target, no Windows SDK) or, without cargo, downloaded from the release with its sha256 checked. Hot reload unloads the old copy completely before the new one loads. `engine_command` works right after an attach: the agent replays a real player command's origin, typing `/testfor @s` in chat itself the first time, only while the HUD alone shows. `engine_screenshot` copies the frame the game presents into a PNG at your path, open screens included, without the game's own screenshot (no toast, nothing in its gallery). See [In-Game Agent](docs/engine.md).
- Input lock (`game_input_lock`, `sculk game lock`): keeps your own keyboard, mouse and controller out of the game while sculkwire plays through the agent, with `on`/`off`/`auto` modes, F9 to take control and give it back, the game's own camera permission, an action-bar badge, and the desktop focus watcher of a window-mode game. The lock fails open, also when the agent unloads. `player_act` and `sculk bench` use the engine route through the built-in input provider while the agent is attached; `input.attack` and `input.use` report the crosshair target and hold their button on request, so `player_act mine` breaks blocks on the engine route.
- Game settings (`game_settings`, `sculk game settings`): the game's own options by their `options.txt` tag, changed through the game when the agent is attached and in the file when it is not, with every changed value put back by `game_stop`. Both routes answer in the game's units (`gfx_viewdistance` in chunks), and the int-choice options such as `game_thirdperson` work through the agent.
- World settings (`world_settings`, `sculk world settings`): game rules, difficulty, game type, time and weather of a test world, through the game when attached and in `level.dat` otherwise, and only ever for `sculkwire-*` worlds.
- Menus and screens (`game_ui`, `sculk game ui`): the current screen and its stack, its controls, and keys, text, clicks and scrolling through the game's own UI, so menus work in the background and on Windows without the foreground. Every input is refused on a store, Marketplace, Minecoins, Dressing Room or persona editor screen except `Escape`; on OreUI pages the agent reads the page's route and allows clicks only on the Play screen and the Settings option pages. A click the game did not read is reported (`ui.click_input`). `game_input` and the `game_launch` sign-in recovery take this route while the agent is attached.
- Inventory, containers, crafting and stations (`player_inventory`, `container`, `craft`, `interact`, `screen`; `sculk player inventory`, `sculk container get`, `sculk craft match|run`, `sculk interact block|entity`, `sculk screen state|move|act|close`): the player's inventory, attributes and armour and any block container, with enchantments by name and the contents of shulker boxes and bundles; recipe matching through the game's own lookup; using a block or an entity like a right click, with `changed` when the used block's state changes (a lever, a button); and the open screen's containers and state, moving items (also into a bundle, through the game's own bundle insert, and on crafter, hopper, dispenser and dropper screens) and running its own action (craft 2x2 and 3x3, trade, stonecut, smelt, enchant, anvil, grindstone, smithing, loom with the requested pattern, cartography, beacon, brewing) as the game's own item requests; `screen close` closes the chat screen too. `player_inventory` and `container get` fall back to the helper pack without the agent.
- Extensions can supply the agent DLL for game folders they recognise (`registerAgentSource`). CI builds the agent for `x86_64-pc-windows-msvc` on Linux and Windows, and the release publishes `sculkwire-agent-<version>-x86_64-windows.zip` with its `.sha256`.
- `sculk mcp` answers every request it already received when the client closes stdin, and exits only after the answers left stdout (at most 30 s). Before, a client that wrote its requests and closed stdin at once could get a cut-off answer when it read slower than the pipe buffer filled.
- `player_act` drives a Linux desktop-mode game through the attached agent, `select_slot`, `hold` and `mine` included; before, every action asked for window or headless mode.
- `player_job`: every ended job names its `stopReason` (the play loop's own stop, or `error` when the run failed).
- `game_status` follows the game process, so a crashed game is no longer `running` or `ready`, and the `/connect` manual step shows only while no `/connect` client is attached.
- `game_registry` falls back to the helper pack's Script API when `/connect` answers an empty list (the retail game does). `game_input` reports its route, and `game_reload` no longer promises a rejoin.
- `input.attack` and `input.use` no longer miss about one click in three with the crosshair steady on a mob (measured on retail on a husk held still 2 blocks away: 13 of 20 attacks saw it before, 20 of 20 after; sampled every 17 ms the pick read entity, entity, nothing in every tick): the game's crosshair pick is empty in one frame of every tick, so a click that finds it empty now waits for the next main-thread drain that holds it (at most 75 ms) and reads the target and clicks there. A click sent within a tick of a view change still sees the old view's target: the game computes the pick once a tick.
- The agent's tick stream no longer keeps reporting the player at the old world's spawn after a world change (a left world, a failed join, a rejoin): the client tick now reads the local player only through a registry the game used in the last client frame, newest capture first, so the stream follows the new world's player within a frame or two, and `player.state` reads that same registry. A `tick` sent while the agent has no current reading of the local player carries `position`, `rotation`, `velocity` and `onGround` as null instead of the last position, so the client skips it.
- A session that changes worlds a third or fourth time keeps its tick stream: the agent now reuses the slot of a game object it no longer sees stepping, instead of running out of slots and never recognising the new world's server.
- `game_reload` and `game_launch` copy the project's packs over the project's existing folders. Before, a folder left by an earlier launch was reused as it was, so edits never reached the game.
- `game_launch` width and height set the game's resolution under gamescope.
- Game files tools find the game folders of every detected Wine or Proton client install, not only mcbe-gdk-linux.
- Knowledge lookups suggest near names for misspelt ids (`gvie` suggests `give`), and stable Script API symbols are described from the plain typings.
- `script_profile` places native bindings at their call site, and BDS session packs report path `.` when the project folder is the pack.
- `play` names the carried food at full hunger instead of `Food: none`.

## v0.1.0

First release.

- Versioned knowledge for stable and preview: docs, Script API, components, commands, Molang, vanilla examples and changelogs.
- Pack validation with file, line, column and rule code for every problem, including Regolith projects.
- Schemas from [rockide/schemas](https://github.com/rockide/schemas) by default, kept on rockide's newest GitHub release: the source tarball of the newest release tag goes into the cache on first use, the tags are checked again at most once a day (`sculk knowledge update` checks at once), a new release is unpacked and checked before it replaces the old copy, and the last copy is used offline. Without a copy, validation goes on with the engine schemas and `component_lookup` without rockide, and both say so in a `rockide.note`.
- The validator tries rockide first, then the engine schemas from bedrock-samples. Measured on vanilla 1.26.60.5: rockide covers 7476 of 7862 JSON files (the rest are texture lists, `texts/languages.json` and manifests, which have their own check), and 86% of injected entity, block and item errors are caught instead of 18% with the engine first (unknown components and fields), for 9 more held-out vanilla false positives in 3816 files. `--rockide <dir>` (CLI) and `rockide_dir` (MCP) pick a checkout. Results carry `rockide` (release, commit and newest release seen).
- Loot `match_tool` conditions accept a number or `{range_min, range_max}` for `count`, `durability` and enchantment `levels`, as Mojang documents.
- `component_lookup` and `sculk component` include the rockide definition per scope (entity behaviors and components, block and item components, client files): description, properties with types, defaults, allowed values and bounds at the `format_version` matching the channel's game version, plus every version and the versions where it changed.
- Every data source updates on its own, at most one cheap check per source per day, without blocking a tool call and keeping the last copy offline or after a failure. The version pins (samples tags, npm builds, BDS builds, changelog titles) are re-resolved in the background once a day. The MCP server then checks out a newly pinned samples tag while the previous checkout answers, downloads a newer BDS build for the next `bds_check`/`gametest_run`/session, fetches changelogs again when a new article appears and re-indexes the creator docs when `main` moves, all in the background. New typings are installed on next use with the previous install as fallback. A CLI command only refreshes the pins in the background and exits at most 3 seconds after its output; `sculk knowledge update` refreshes everything in the foreground, including installed BDS builds.
- `sculk knowledge status` and `knowledge_versions` list every data source with the version in use, the newest seen upstream and the last check.
- Bedrock Dedicated Server: load checks, headless GameTest runs, sessions and script profiling. A Regolith project whose profile runs filters is built with rgl first and BDS loads the built packs; diagnostics point at the source files (through source maps for generated scripts), and a failed build is a `regolith.build-failed` error with no server started.
- Live game bridge on Windows and Linux: private single-player test worlds, deploy and reload, content log, queries, screenshots and input, with screen-aware sign-in recovery at launch. Deploys leave one folder of the project per pack uuid (a fresh build goes into the project's rgl export folder when there is one) and warn about other packs that share the uuid.
- Player control (`player_act`, `player_job`, `player_state`): human-like camera, pathfinding and combat skills, and the background `play` loop with an optional decision model as advisor.
- Game files of an installed PC (GDK) copy (`game_builds`, `game_vanilla_packs`, `game_extract_pack`, `sculk gamefiles`): game version, the per-version `vanilla_1.x` packs and their extraction from `.brarchive` into plain folders.
- Extensions: packages listed in `SCULKWIRE_EXTENSIONS` or placed in `<config>/extensions` add MCP tools, CLI commands and an in-process input provider for `player_act`; a broken extension is skipped with one stderr line. An extension may also supply the in-game agent's DLL for game folders it recognises (`registerAgentSource`), which replaces the built-in build at attach.
- `sculk bench` measures the player skills in built arenas.
- Installers. `install.sh` (Linux and macOS) and `install.ps1` (Windows) install the newest release into a managed layout, put `sculk` on PATH and run `sculk setup`. Flags: `--yes`, `--decision`, `--register`, `--channel`.
- Automatic updates. A managed MCP server checks for a new release at most once a day in the background, installs and checks it, and switches to it for the next session. `sculk update` (with `--check`, `--channel release|main|off` and `--rollback`) does the same by hand.
- `sculk setup --register omp,claude` registers the stable launcher with omp and Claude Code and prints the JSON for any other client. `sculk setup --yes --decision <provider>` runs without questions.
- `sculkwire_version` tool and a `version` line in `sculk doctor`: running version, channel, newest version seen and whether an update waits for the next session.
- Dependabot opens PRs for the npm dependencies.
